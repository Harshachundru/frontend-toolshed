# How to use this guide

Every topic follows the same pattern: what it is and how it works, then the interview questions with short model answers, then one STAR story you can adapt to your own experience. Interviewers at mid and senior level care less about definitions and more about whether you can explain trade-offs and tell a believable story about using the thing in production.

**The STAR format**

- **Situation**: the context in one or two sentences (team, product, constraint).
- **Task**: what you specifically were responsible for.
- **Action**: what *you* did, in concrete steps. This should be the longest part.
- **Result**: the outcome, with a number if you have one, and what you learned.

The STAR examples here are templates. Replace the product, numbers and details with real ones from your own work before the interview. An invented story falls apart under one follow-up question.

**A two-week study plan**

| Days | Focus | Practice |
| --- | --- | --- |
| 1 to 3 | JavaScript core: closures, `this`, event loop, promises | Predict-the-output questions; write `debounce`, `throttle`, `Promise.all` by hand |
| 4 to 5 | TypeScript | Type a real API response; write a generic hook |
| 6 to 8 | React core, hooks, state management | Build a small app with search, fetch, pagination |
| 9 | HTML, accessibility, CSS | Build a responsive layout with Grid and Flexbox from memory |
| 10 | Browser, security, networking | Explain cookies, CORS, XSS and CSRF out loud |
| 11 | Performance | Profile a slow page in Chrome DevTools and Lighthouse |
| 12 | Frontend system design | Design an autocomplete and a news feed out loud, 35 minutes each |
| 13 | STAR stories | Write 8 stories, rehearse each in under 2 minutes |
| 14 | Mock interview | One coding round, one design round, one behavioural round |

**What the interviewer is scoring**

1. Fundamentals: can you explain *why*, not just *what*.
2. Problem solving: do you clarify requirements, think aloud, and test your own code.
3. Trade-offs: do you know when *not* to use Redux, memoisation or a library.
4. Production sense: performance, accessibility, security, testing, monitoring.
5. Collaboration: code review, mentoring, working with design, product and backend.
